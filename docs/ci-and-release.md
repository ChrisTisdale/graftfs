# CI and release

## CI

`.github/workflows/build.yml` runs on pushes and pull requests targeting `main` and `release/*`, and is the
source of truth for what must pass. Three jobs:

**`build`** — matrix of `{release, debug}` × `{ubuntu-latest, windows-latest, macos-latest}`, `fail-fast: true`.

- debug: `cargo build --all-features --all-targets` then `cargo test`
- release: `cargo build --release --all-features --all-targets`

Tests only run in the debug leg, but the build runs on all three platforms — platform-gated code that does
not compile everywhere fails the matrix.

**`build-checks`** — `cargo fmt --all -- --check` and the pedantic/nursery clippy line.

**`build-docs`** — `cargo doc`.

All jobs use `dtolnay/rust-toolchain@stable`, so the effective toolchain is current stable, not the MSRV
declared in `Cargo.toml`.

## Release

`graft/CHANGELOG.md` is generated by [`cargo smart-release`](https://github.com/Byron/cargo-smart-release)
from Conventional Commit subjects. Entries carry `csr-id` markers and
`<csr-read-only-do-not-edit/>` blocks.

**Do not hand-edit `CHANGELOG.md`.** Write a well-formed commit subject instead; the changelog is regenerated
at release time. Release commits appear in history as `Release graftfs v<version>`.

The version lives in `graft/Cargo.toml`. The `xtask` crate is `publish = false` and is versioned
independently — it is not released to crates.io.

## Distribution artifacts

`cargo xtask dist` produces the binary plus man pages. See [`../xtask/AGENTS.md`](../xtask/AGENTS.md).
